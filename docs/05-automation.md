# 05. 자동화 — 가능성과 한계

판단 방식: 기존 가정 → 근본 사실 → 결론. 공식 문서 재확인이 필요한 사실은 `[미검증]` 으로 표시했다(이 문서는 외부 계정에 접속하지 않고 작성됨).

## 5.1 게시 — Instagram

| 기존 가정 | "API 로 캐러셀을 자동 게시할 수 있다" |
| --- | --- |
| 근본 사실 | ①Meta 의 Instagram 콘텐츠 게시 API(Content Publishing)는 **프로페셔널 계정(비즈니스/크리에이터)**만 대상이다. ②캐러셀은 항목(이미지/영상) 컨테이너를 만든 뒤 묶음 컨테이너를 만들어 게시하는 다단계 호출이다. ③이미지는 파일 업로드가 아니라 **공개 URL 에서 Meta 가 가져가는 방식**이다 → 렌더 PNG(또는 JPEG)를 공개 접근 가능한 저장소에 올려야 한다. ④캐러셀 항목 상한 10개, 계정당 24시간 API 게시 상한이 있다 [미검증 — 상한 수치는 버전마다 바뀌어 왔으므로 착수 시 공식 문서로 재확인]. ⑤이미지 형식은 JPEG 만 허용되는 것으로 알려져 있다 [미검증]. ⑥Meta 앱 생성·액세스 토큰 발급이 필요하고, 토큰은 만료·갱신 관리가 필요하다. 본인 계정에 한정한 사용은 앱 심사 없이 가능한 범위가 있다 [미검증]. |
| 결론 | 기술적으로 가능하나 **선결 조건 3개**: 프로페셔널 계정 전환, Meta 앱·토큰, 공개 이미지 호스팅. MVP 는 `publisher-manual`(업로드 묶음 + 캡션 복사)로 시작하고, 위 3개가 확보되면 API 게시를 켠다. 어떤 경우든 사람 승인 뒤에만 호출. |

## 5.2 게시 — YouTube Shorts

| 기존 가정 | "Data API 로 Shorts 를 자동 업로드할 수 있다" |
| --- | --- |
| 근본 사실 | ①YouTube Data API v3 `videos.insert` 로 업로드한다. Shorts 전용 플래그는 없고 세로·짧은 영상이면 Shorts 로 분류된다(길이 상한 3분으로 확대된 것으로 알려짐 [미검증]). ②업로드 1회 = 1,600 할당량 단위, 기본 일일 할당량 10,000 단위 → 하루 약 6회 [미검증 — 현행 수치 재확인]. ③**감사(audit)를 통과하지 않은 API 프로젝트로 올린 영상은 비공개로 고정**된다는 정책이 있다(2020-07 이후 생성 프로젝트) [미검증 — 현행 유지 여부 확인]. 공개 전환하려면 감사 신청이 필요하다. ④OAuth 동의·리프레시 토큰 관리가 필요하다. |
| 결론 | 자동 업로드는 가능하나, 감사 전에는 **비공개 업로드 → 사람이 YouTube Studio 에서 공개 전환**이 현실적인 형태다. 이 방식은 오히려 승인 게이트와 잘 맞는다(최종 공개 버튼을 사람이 누름). |

## 5.3 일정 실행

| 기존 가정 | "정해진 시각에 렌더·게시가 돈다" |
| --- | --- |
| 근본 사실 | ①일정 실행에는 **항상 켜진 실행 주체**가 필요하다: 상시 서버, 클라우드 스케줄러, CI 크론, 또는 집 PC. ②플랫폼 자체 예약 게시는 API 로 쓸 수 있는 범위가 제한적이다 — Instagram 은 API 로 예약 시각 지정이 안 되는 것으로 알려져 있어 우리 쪽 스케줄러가 그 시각에 호출해야 한다 [미검증]. YouTube 는 `status.publishAt` 으로 예약 공개를 지정할 수 있다(단 5.2 ③ 비공개 고정과 충돌 가능) [미검증]. ③CI 크론(예: GitHub Actions)은 정시 실행을 보장하지 않고 수 분~수십 분 지연될 수 있다 [미검증]. |
| 결론 | 렌더·변환처럼 시각이 덜 중요한 잡은 어떤 스케줄러든 된다. "발표 전날 저녁" 같은 게시 시각은 수 분 오차가 허용되므로 CI 크론도 후보지만, 실패 감지·재시도를 위해 **잡 기록이 DB 에 남는 워커**를 권장. 호스팅은 D3 로 확정했다(2026-11-04 사용자): MVP 는 Windows 실행기 + SQLite, M3 에서 재판단. |

## 5.4 이벤트 캘린더 감지

| 기존 가정 | "중요 이벤트를 자동으로 찾아준다" |
| --- | --- |
| 근본 사실 | ①정기 이벤트는 **공식 기관이 연간 일정을 미리 공개**한다: 미 연준 FOMC 회의 일정, 미 노동통계국(BLS) 발표 일정(고용·CPI), 각국 중앙은행 회의, 선거일. 이 원천은 무료이며 형식(HTML/ICS/PDF)이 기관마다 다르다 [미검증 — 원천별 형식 확인]. ②기업 실적 발표일은 기업이 따로 공지하며 한곳에 모은 무료·안정적 원천은 드물다. 상용 경제 캘린더 API 는 유료가 일반적이다 [미검증]. ③돌발 이슈(정책 발표·지정학)는 캘린더로 감지할 수 없다. |
| 결론 | 단계별로: MVP = 사람이 대시보드에 이벤트 입력 + 공식 일정 몇 개(연준·BLS)를 연 1회 수동 일괄 등록. 자동화 단계 = 공식 원천 파서로 주기 수집해 **후보만 제안**(선정은 사람). 유료 캘린더 API 는 수동 입력 부담이 실측으로 확인될 때만 검토. 웹 수집이 필요한 원천은 사용자 규칙상 Aside 경유만 허용되므로, 서버 무인 수집은 공개 API·파일 다운로드 원천으로 한정한다. |

## 5.5 원고 초안 (LLM)

- 가능: 포맷 단(5단) 채우기, 문장 다듬기(발행 언어 기준), 주장 추출.
- 한계: 수치·날짜 환각 위험 → 3단계 출처 검증을 우회할 수 없게 도메인 규칙으로 막는다. 호출당 비용 발생 → [결정 필요 D4].

## 5.6 렌더·영상 합성

- 카드: HTML → PNG 로컬 렌더. 비용 0, 결정적(같은 입력 → 같은 출력).
- Shorts: 이미지 + 자막 + (선택) 음성 → ffmpeg 류 합성. CPU 작업이므로 실행 위치는 사용자 인프라 규칙(무거운 작업은 Windows 실행기)을 따른다.
- TTS 는 외부 서비스면 비용, 로컬이면 품질 실측 필요 [미검증] → [결정 필요 D6].
