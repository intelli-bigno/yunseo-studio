# 06. 대시보드 — 정보구조·화면 흐름·화면 명세

사용자: 운영자 1~2명(최윤서 본인 + 보조). 공개 서비스가 아니다 → 로그인은 운영자 계정만. [호스팅: D3 확정 — MVP 는 Windows 실행기 + SQLite. 인증 방식은 미정]
데이터 규칙은 [01-content-sot.md](01-content-sot.md), 공정·게이트는 [02-sop.md](02-sop.md). **와이어프레임은 [design/wireframes.html](design/wireframes.html)** (PNG: [wireframes.png](design/wireframes.png)).

## 1. 설계 원칙

1. **한 편의 길이 화면의 순서다.** 편성 → 선정(G1) → 작성 → 출처·구분(G2) → 미리보기 → 검수(G3) → 발행 → 성과. 편 상세의 탭이 이 순서 그대로다.
2. **게이트는 사람만 누른다.** 승인·확인 버튼은 자동화가 대신 못 누른다. 자동 검사는 「칸이 비었는가」까지만 보고 결과를 화면에 보여 준다.
3. **구분이 눈에 보인다.** 모든 문장에 구분 기호(■▲◆○)와 밑줄(조사/직접 경험)이 붙고, 편집기·미리보기·카드 출처 장에서 같은 모양이다.
4. **채우기를 부추기지 않는다.** 빈 날을 「쉬는 날로 두기」가 「연구 배정」과 같은 크기의 선택지다. 중요도를 올릴 땐 사유를 받는다.
5. 화면은 유스케이스만 호출한다(04 문서). 화면에서 외부 API 직접 호출 금지.
6. 프리셋은 대시보드에서 편집하지 않는다(정본은 Git — 01 문서).

## 2. 정보구조 (왼쪽 메뉴 6개)

| 메뉴 | 하위 | 용도 |
| --- | --- | --- |
| **오늘** | 오늘의 피드 슬롯 · 막힌 편 · 내가 통과시킬 게이트 · 다음 3일 | 시작 화면. 지금 내가 할 일만 |
| **편성** | **편성 캘린더**(주·월) · 사건 후보함 + 중요도 판정 · **이번 주의 변수** · 릴스 후보 | G1 과 리듬 관리 |
| **콘텐츠** | ① 이전 · ② 이후 · ③ 연구(스레드) 목록 → **편 상세** | 작성·검증·검수 |
| **발행** | **발행 대기열** · 업로드 묶음 · 게시 URL 기록 | 승인본을 내보냄 |
| **성과** | 편별·종별 표 · 수동 입력 · 이후 편 대비 복기 메모 | 해석과 편성 조정 |
| **설정** | 프리셋(읽기 전용) · 금지 표현 규칙 · `TBD` 잔존 경고 | 확인용 |

편 상세 탭: **작성 · 출처·구분 · 연결 · 이력 · 미리보기 · 검수**. 종류에 따라 일부 탭이 달라진다(연결 탭은 ② 이후만 내용이 있고, ①은 「이 편을 가리키는 이후 편」을 보여 주며, ③은 스레드 보기).

## 3. 화면 흐름

```
[오늘] ──▶ [편성 캘린더] ──▶ G1 선정 ──▶ [작성] ──▶ G2 [출처·구분] ──▶ [미리보기] ──▶ G3 [검수] ──▶ [발행 대기열] ──▶ [성과·복기]
              ▲  │ 사건 후보함·중요도                      ▲                                                      │
              │  └▶ [이번 주의 변수] ─────────────────────┼── 지난 주 항목을 ② 이후 편으로 닫는다 ◀──────────────┘
              └─ ② 전용: 선정 뒤 「자료 대기」 → 조건 4개 충족 시 작성으로
수정 발생: [이력] 탭에 이유 기록 → 기존 승인 무효 → G3 다시
릴스: 승인된 피드를 골라 → 새 주장 없이 영상 구성 → 승인 → 발행 대기열(릴스 탭)
```

## 4. 화면 명세

| 화면 | 목적 | 주요 동작 · 규칙 |
| --- | --- | --- |
| **편성 캘린더** | 하루 피드 1칸 + 주 1회 스토리 + 릴스 1~2칸을 한눈에 | 칩 모양으로 종류 구분(검정=사건 연동 ①②, 흰색=연구 ③). 같은 날 ① 둘·②가 3일째 자료 대기 같은 규칙 알림은 **막지 않고 알린다**. 쉬는 날 사유 기록. 슬롯 배정은 02 문서 §3.3 |
| **사건 후보함** | 후보 사건에 중요도 판정 | 자동 수집 결과를 a~e 질문 칩(기대 변화·갈림·자료 확인·운영자 해석·후속 변수)으로 보여 주고 `major`·`watch`·제외(`skip`)는 **사람이 누른다**. 자동 제안(종류별 기본 점검표)은 `watch` 를 넘지 않는다. 판정을 **올릴 때** 사유 입력 필수, 「되돌리기」로 자동 제안에 복귀 |
| **일정 수집 · 수동 입력** (`/schedule/events`) | 공식 일정이 어디까지 들어왔는지 보고, 파일 원천이 없는 일정을 손으로 넣는다 | 원천별 마지막 수집 시각(KST)·저장 수·결과(실패는 오류 문장), 일정 변경 이력(이전 → 이후), 앞으로 30일 전체 일정(자동 제안과 판정), 수동 입력 폼(제목·날짜·시각 KST·종류·**확인 출처 URL 필수**·메모)과 삭제. 수집한 일정은 지우지 않고 후보함에서 「제외」로 숨긴다. 기계 판독 원천이 없는 기관(ECB·BoE·BoJ)은 공식 페이지 링크만 안내 |
| **이번 주의 변수** | 스토리·하이라이트 한 장 | 날짜·요일·시간대가 가장 크게. 줄마다 구분 표시와 일정 출처. 일정이 바뀌면 이유 입력 없이 검수로 못 간다. 지난 주 항목은 이후 편 링크로 닫는다. 오른쪽에 9:16 미리보기 |
| **작성 (3종)** | 종류별 단 폼 | 같은 틀(왼쪽 단 목록·가운데 폼·오른쪽 점검)에 단만 바뀐다. ①5단 · ②4단(+ 이전 편 시나리오 응답 표) · ③ 스레드 단계(아이디어·조건·실패·도구·후속). 필수 칸이 비면 다음 탭으로 못 넘어간다 |
| **출처·구분 편집기** (G2) | claim 별 구분·출처·기준 시점 확인 | 왼쪽: 구분 표시를 입힌 본문, 오른쪽: 선택한 claim 상세(종류·근거·출처 URL·발행처·접근일·원문 인용·등급·기준 시점). 필터(미확인·재확인 필요·경고). 「원문과 대조했음 — 확인」은 사람만. 근거 없는 해석(`based_on` 없음)은 경고로 G2 를 막는다 |
| **이전 ↔ 이후 연결 보기** | 이전 편이 한 일을 이후 편이 닫는지 | 왼쪽 읽기 전용(발행된 이전 편), 오른쪽 응답. 시나리오 전부 응답·확인할 것 전부 처리·판단 변경은 이유와 이전 편 이력 연결. 닫힘 N/M 표시. 이전 편이 없으면 「사전 시나리오 없음」 |
| **이력** | 수정 이력 목록과 입력 | 변경 종류(정정·갱신·명확화), 이유(필수), 독자 문구, 후속 게시물 연결(`update` 는 필수 또는 기한). 입력 시 승인 무효 안내 |
| **미리보기** | 카드·스토리·릴스 표지를 폰 크기로 | 휴대폰 크기, 재렌더, 시각 프리셋 적용 상태(`TBD` 잔존 경고) |
| **검수** (G3) | 최종 발행 판단 | 02 문서 §5.3 체크리스트, 승인/반려(사유 필수), 승인 해시 표시. ②는 이전 편과 나란히 보기 |
| **발행 대기열** | 승인본을 내보내고 기록 | 피드·스토리·릴스 탭. 행마다 종류·상태·**해시 일치 여부**. MVP: 업로드 묶음 받기 + 캡션 복사 + 게시 URL 수동 입력. 승인 뒤 수정된 편은 「불일치」로 막힘 |
| **성과** | 편별 지표 | 수동 입력 폼, 편별·종별 표. ②는 이전 편 대비 복기 메모 |
| **프리셋** | 현재 활성 프리셋 확인 | 읽기 전용(변경은 Git), 스키마 오류·`TBD` 잔존 경고 |

## 5. 상태 표시

- 편 카드 색을 쓰지 않는다 — 상태는 글자(`draft`·`verified`·`approved`…)와 칩 모양(검정=게이트 대기·막힘, 흰색=진행·완료)으로 보인다.
- 「막힌 편」은 오늘 화면 맨 위: 어느 게이트에서 무엇이 비었는지 한 줄(예: 「G2 · 시나리오 3 미응답」).

## 6. 자동화 단계에서 추가

- 사건 후보함 자동 수집(수락/무시), 게시 작업 큐(예약 시각·상태·재시도·실패 로그)
- 계정 연결 상태(토큰 만료일 표시 — 토큰 값 자체는 화면에 절대 표시하지 않음)
- 성과 자동 수집 + 프로필 방문→팔로우 추이
- 릴스 후보 점수 제안(사람이 확정)

## 7. 언어

대시보드 UI 언어: 운영자 언어(한국어/영어) [결정 필요 D9]. 콘텐츠 미리보기는 발행 언어(프리셋, 기본 영어·미확정 [결정 필요 D10])로 보여준다. 시안은 한국어 자리표시 문구와 영어 표지 한 장으로 두 언어의 틀을 같이 확인했다([design/](design/README.md)).
