# 카드 템플릿 사양 — 레퍼런스 구조를 우리 정본에 맞춘 것 (초안 v1)

레퍼런스에서 가져온 것은 **구조**뿐이다([README.md](README.md) §3). 이 문서는 그 구조를 정본([01-content-sot.md](../../01-content-sot.md))의 규칙에 맞춰 **카드 사양**으로 옮긴다.
예시 한 세트: [example/cards-a.html](example/cards-a.html)(시안 A) · [cards-b.html](example/cards-b.html)(시안 B), 렌더 [example/render/](example/render/), 비교 [compare.html](compare.html).
사건 예시는 「미국 중간선거 이후, 시장이 다시 계산할 세 가지」(영문 `Three things markets will re-price after the US midterms`) — 문구는 [content/examples/pre-issue/us-midterms-three-repricings.yaml](../../../content/examples/pre-issue/us-midterms-three-repricings.yaml) 를 따르되 **사실 수치는 자리표시**, 채널명·운영자·고지 문구는 미정 자리표시, 발행 언어는 프리셋 기본(영어)이다.
모든 카드에 `SAMPLE` 표시와 「draft, cannot be published」가 있다 — 예시는 발행 불가다.

## 1. 원칙

1. **한 장 = 질문 하나.** 5단의 각 단이 이미 질문(`stages[].question`)이므로 질문 상자가 곧 단의 제목이다.
2. **한 장 = 한 메시지의 그림 + 한 문단의 글.** 위 ≈1/3 은 도식·차트 자리, 아래 ≈1/2 은 글 영역.
3. **구분은 색이 아니라 기호·밑줄.** ■ 사실 · ▲ 시장 반응 · ◆ 해석 · ○ 시나리오, 실선=조사 · 점선=직접 경험(흑백에서도 동일).
4. **출처·기준 시점은 장마다 보인다** — 푸터에 기준 시점, 마지막 장에 출처.
5. **가져오지 않는 것**: 사진·말풍선 모양·이모지·인물 인용·로고·문구. 색 하나(강조)와 글 위계만 시각 시스템 A·B 를 따른다.

## 2. 판형 · 그리드 (1080×1350 기준, 4:5 → 판형은 [결정 R1])

| 구역 | 위치(px) | 내용 |
| --- | --- | --- |
| 헤더 | y 56–120, 좌우 여백 72 | 좌: 종류 표시(① Before the event) · 우: `NN / 07` + `SAMPLE`(초안일 때만) |
| 본문 영역 | y 150–1200 | 아래 세 구역이 위에서 아래로 쌓인다 |
| ├ 도식 구역 | 높이 440, 아래 간격 24 | 차트·개념도·체크리스트(단마다 다름) |
| ├ 질문/답 | 질문 38 px 직각 상자(좌) → 16 px 아래 답 띠(우, 강조색) | 질문=단 질문 · 답=한 줄 단언(주장형 헤드라인) |
| └ 글 영역 | 간격 44, 본문 36 px / 1.5 | ◆·○·▲ 기호로 시작하는 문장 2~3개, 핵심구에 밑줄 |
| 푸터 | y 1250–1294 | 좌 채널명 · 중 `As of [기준 시점]` · 우 `Next › 다음 단`(마지막 장은 `Follow-up › ②`) |

- 좌우 여백 72 px(6.7 %) — 프로필 격자(3:4 로 잘리는 경우 좌우 ≈34 px)에서도 핵심이 남는다 [미검증].
- 표지는 같은 헤더·푸터 틀에 **도식 구역 440 → 제목 92 px 3줄 → 부제 36 px → 운영자 크레딧 26 px**.
- 마지막 장(출처)은 질문/답이 없고 제목 64 px + 구분 4행 + 점선 상자 2개.

## 3. 타이포 · 색 토큰

| 층 | 크기 | 굵기 | 비고 |
| --- | --- | --- | --- |
| 표지 제목 | 92 | 700(A 세리프) / 800(B 산세리프) | 90자 이내, 3줄 |
| 질문 · 답 | 38 | 700 | 각 8단어 이내 권장 |
| 본문 | 36 (밀도 높은 카드는 34) | 400, 핵심구 700+밑줄 | 카드당 45단어 이내 권장 |
| 보조·푸터·도식 라벨 | 24–28 | 400 | 폰 화면(≈0.36배)에서 ≈9pt 이상 |

크기 비율 **92 : 38 : 36 : 24 ≈ 3.8 : 1.6 : 1.5 : 1** — 레퍼런스(2.7 : 1.06 : 1)보다 본문 대비 표지를 더 키우고, 질문·답은 본문보다 한 단계 크게 했다(말풍선 모양이 없는 대신 크기·굵기로 위계).

| 토큰 | 시안 A (Paper & Ink) | 시안 B (Signal) |
| --- | --- | --- |
| 바탕 `--bg` | #F7F4EE | #FFFFFF |
| 글자 `--ink` | #151515 | #0E0E0E |
| 보조 `--mut` | #6A655C | #666666 |
| 선 `--rule` | #D9D3C7 | #E2E2E2 |
| 강조 `--acc` | #1F5F5B | #C2410C |
| 제목 서체 | 세리프(시스템 서체 자리표시) | 굵은 산세리프 |

색은 **바탕·글자·보조·선·강조 1색**(총 5값) — 시각 시스템 A·B 의 규칙과 동일하고, 방향 색(상승=초록 등)은 쓰지 않는다. 서체는 시스템 서체 자리표시다 [결정 D5].

## 4. 슬롯별 사양 (포맷 ① `pre-issue-5`, 7장)

| # | 슬롯 | 도식 구역 | 질문 상자(단 질문) | 답 띠(헤드라인) | 글 영역 | 구분 기호 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `cover` | 개념 마크(경로가 결과에서 갈라짐) | — | — | 제목 + 한 줄 부제 | — |
| 2 | `why_it_matters` | 결과 → 기대 → 가격 3칸 | Why does this matter? | A result is a change in expectations | 문장 2 (해석) | ◆ |
| 3 | `market_expectation` | **차트 자리표시**: 기준 구간·오늘 선·라벨 `[값]` | What does the market assume now? | The baseline is already in prices | 문장 2 (해석) | ▲(차트) · ◆ |
| 4 | `scenarios` | 결과에서 세 갈래로 갈라지는 개념도(확률·수치 없음) | What if the result differs? | Three readings, not predictions | ○ 3행: 조건 → 읽는 법 | ○ · ◆ |
| 5 | `transmission` | 경로 3행: 경로 → 닿는 곳 | How does it reach prices? | Three paths, result to prices | ◆ 3행: 경로 이름(밑줄) + 설명 | ◆ |
| 6 | `after_checks` | 체크박스 3행 + 「어디서」 | What do I check afterwards? | Three signals you can verify yourself | **반전 상자** 한 문장(독자가 손에 쥘 것) | — |
| 7 | `sources` | — | — | — | 구분 4행(■▲◆○) + 운영자 해석·고지 문구 점선 자리 | ■▲◆○ |

- **답 띠는 단언형으로 쓴다.** 예시 YAML 의 `headline` 중 2~5단은 라벨형(「What the market seems to assume today」)이라 질문과 겹친다 → 답 띠용 단언 문구를 렌더에서 새로 썼다. YAML 은 바꾸지 않았다 [결정 R5 와 함께 후속].
- 도식 구역은 **수치 없는 개념도**이거나 **자리표시 차트**다. 실제 수치는 `claims[]` 의 출처·기준 시점이 채워져 `verified` 가 된 뒤에만 넣는다.

## 5. 데이터 → 카드 매핑

| 카드 요소 | 데이터 필드 (정본) | 필수·검사 |
| --- | --- | --- |
| 종류 표시 | 포맷 `kind` (`pre_issue` → ①) | 3종 모두 같은 틀, 표시·번호만 다름 |
| 표지 제목 | `cover.title` | ≤ 90자(프리셋) |
| 부제 | `cover.hook` | — |
| 질문 상자 | 포맷 프리셋 `stages[].question`(언어별 값 필요 → [R5]) | 5단 모두 |
| 답 띠 | `stages.<단>.headline` | 한 줄 단언 |
| 글 영역 문장 | `points[]` · `items[]` · `paths[]` · `checks[]` | 수치·고유명사·날짜가 든 문장은 `claims[]` 와 연결 |
| 구분 기호 | `claims[].kind` (`fact` ■ · `market_reaction` ▲ · `interpretation` ◆ · `scenario` ○) | **한 문장 한 종류** |
| 밑줄 | `claims[].basis` (`researched` 실선 · `experienced` 점선) | 직접 경험을 조사처럼 쓰지 않는다 |
| 푸터 기준 시점 | 편 `as_of` (ISO 8601 + 시간대) | **모든 카드** — claims 의 가장 늦은 `as_of` 이상 |
| 출처 장 | `claims[].source` (`publisher` · `accessed_at` · `quote` · `tier`) | ■·▲ 마다 1건 이상 |
| 운영자 해석 칸 | `operator_view` | 비면 `verified` 불가 → 카드에 「not written yet」 |
| 시나리오 | `scenarios.items[]` | **둘 이상**, 확률·목표가 숫자 금지 |
| `SAMPLE` 표시 | `status: draft` | `verified` 가 되고 `verificationBlockers` 가 비면 사라진다 |

## 6. SoT 규칙을 카드에서 지키는 방식

| 규칙 (01 §2·§5) | 카드에서의 모습 |
| --- | --- |
| 사실/시장 반응/해석/시나리오 구분 | 문장 앞 ■▲◆○, 마지막 장 범례 |
| 조사 vs 직접 경험 구분 | 실선 vs 점선 밑줄, 마지막 장 범례 |
| 출처·기준 시점 없는 주장 금지 | 차트 아래 `Source … as of …` 필수 줄, 푸터 기준 시점, 7장 출처 |
| 시나리오 둘 이상·확률 없음 | 4장: 세 갈래 + 「not predictions」, 확률 숫자 필드 없음 |
| 독자가 손에 쥘 것 | 6장 체크리스트 + 닫는 상자 |
| 운영자 해석 필수 | 7장 점선 자리: 「not written yet [required before review]」 |
| 투자 권유·수치 단정 금지 | 예시에 매수·매도 표현·목표가·확률 없음. 금지 표현 검사 통과 |
| 이후 편과 연결 | 7장 푸터 `Follow-up › ②`, 6장 확인 항목을 ②가 `check_results` 로 닫음 |

금지 표현·외부 자원·두 안 동기화는 `packages/presets-schema/src/card-example.test.ts` 가 검사한다.

## 7. 시각 시스템 A·B 와 맞물리는 방식

같은 마크업에 body 클래스(`th-a` / `th-b`)만 바꾼다 — **구조(구역·질문/답·글 영역·푸터)는 시스템과 무관**하고, 시스템이 바꾸는 것은 토큰과 표지 틀뿐이다.

| | 시안 A — Paper & Ink | 시안 B — Signal |
| --- | --- | --- |
| 헤더 틀 | 위쪽 선 + 종류 기호 ① (기존 표지 틀 그대로) | 왼쪽 위 **번호 블록 01**(기존 표지 틀 그대로) |
| 푸터 틀 | 가는 선 + 3열 텍스트 | 검정 하단 띠 + 흰 글자(기존 B 표지 틀 그대로) |
| 제목·단언 서체 | 세리프(표지·출처 제목만) · 나머지 산세리프 | 굵은 산세리프 |
| 질문 상자 / 답 띠 | 직각 상자 / 청록 띠 | 직각 상자(선 4px) / 오렌지 띠 |
| 닫는 상자 | 잉크색 반전 | 잉크색 반전 |
| 레퍼런스 구조와 | 본문 위계가 **부드럽다**(매거진 느낌) | 종류 번호·띠가 레퍼런스의 **고정 앵커**를 더 강하게 만든다 |

- 기존 시안의 **표지 틀·푸터·강조 1색·구분 기호 규칙을 그대로 쓰고**, 레퍼런스에서 온 것은 본문 카드의 **질문/답 구조와 글 영역**뿐이다 — 기존 A·B 본문 카드(`docs/design/visual-*.html`)를 대체하지 않고 확장한다.
- **추천은 A 유지**(기존 판단과 동일): 질문·답 구조가 들어와도 A 의 매거진 인상이 유지된다. 다만 영어 제목에서는 B 가 더 안정적이라는 기존 [미검증] 단서가 남아 있다 — 이번 렌더(시스템 서체)에서 A 영어 세리프 제목은 무리 없이 읽혔지만 폰 실기 확인은 하지 않았다.
