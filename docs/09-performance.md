# 09. 성능 — 렌더 전략·캐시·이미지·서체·번들·긴 목록·메모리

대시보드(`apps/dashboard`)를 **측정으로** 고친 기록이다. 수치는 전부 `scripts/perf/` 하니스로 같은 방법·같은 경로 목록을 전후에 돌린 값이고(`docs/perf/before.json`·`after.json`), 브라우저로 잴 수 있는 값(Lighthouse 점수·LCP·INP·CLS)은 **미측정**으로 표시한다(§10).

## 1. 결과 한눈에

| 경로 | 첫 화면 전송량 전 → 후 | 변화 | 이미지 전 → 후 |
| --- | --- | --- | --- |
| `/` 오늘 | 718.8 → **618.7** KB | −14% | 148.6 → 48.2 KB |
| `/schedule` | 651.6 → **569.4** KB | −13% | 118.2 → 35.8 KB |
| `/schedule?view=month` | 539.3 → **456.9** KB | −15% | 118.2 → 35.8 KB |
| `/content` | 489.9 → 489.8 KB | 0% | — |
| `/content/P-1104?tab=write·sources·review` | 539.1·539.2·497.0 → 538.9·539.0·496.7 KB | 0% | — |
| `/content/P-1104?tab=preview` | 1490.5 → **532.7** KB | **−64%** | 999.4 KB(PNG 8장) → 42.1 KB(WebP 8장) |
| `/publish` | 631.7 → **550.1** KB | −13% | 118.9 → 37.2 KB |
| 9경로 합 | 6097 → **4792** KB | −21% | |

- **줄어든 것은 이미지뿐이다.** 서체(경로당 230~380 KB 추정)·프레임워크 JS(gzip 130 KB)가 첫 화면의 나머지 80%를 차지하고, 둘은 이번에 건드리지 않았다(§6·§7에 이유).
- JS(gzip)는 **전후 동일**(경로당 136.5 / 편 상세 139.9 KB). 화면 코드는 합쳐서 8 KB 남짓이라 쪼개서 얻을 것이 거의 없다.
- 서버 응답 p50 은 정적 경로 2 ms 안팎 그대로, 동적 경로는 +0.0~1.5 ms(유스케이스·SQLite 층 비용, §3). 서버 메모리(RSS)는 이미지 변환기(sharp)가 뜨면서 **+약 70 MB**(§5).

## 2. 화면별 렌더 전략

기본은 **서버 컴포넌트**다(JS 를 보내지 않는다). 브라우저에서 상태가 필요한 부분만 **클라이언트 섬**(`components/`)이다. 정적으로 만들 수 있으면 정적, 쿼리(`?view`·`?kind`·`?tab`)를 읽으면 Next 규칙상 요청마다 렌더다.

| 화면 | 전략 | 근거 | 클라이언트 섬 |
| --- | --- | --- | --- |
| `/` 오늘 | 정적 + **60초 재검증(ISR)** | 요청별 입력이 없다. 데이터는 사람의 클릭(분 단위)으로만 바뀐다 | 없음 |
| `/publish` | 정적 + 60초 재검증 | 같음 | 없음 |
| `/schedule` | 서버 렌더(요청마다) | `?view=month` 쿼리 | 사건 후보함 판정 버튼 |
| `/content` | 서버 렌더 | `?kind` 쿼리. 행은 서버 컴포넌트 | 없음 |
| `/content/[id]` | 서버 렌더 | `?tab` 쿼리 | **열린 탭의 편집기 하나**(작성·출처·미리보기·검수) |
| 전역(레이아웃) | 서버 + 섬 2개 | 사이드바 숫자는 서버, 현재 메뉴 강조·키 입력만 브라우저 | `Nav`(경로 강조), `KeyNav`(키 입력, 대화상자는 지연 로드) |
| `/api/cards/[file]` | 요청마다 + **ETag 304** | 렌더 폴더의 PNG 가 바뀔 수 있다 | — |
| `/api/palette` | 요청마다, 브라우저 60초 재사용 | 빠른 이동 색인 | — |

- 동적 경로의 요청당 서버 비용은 p50 4~6 ms 로 체감 병목이 아니다(§10). 그래서 쿼리를 경로 세그먼트(`/schedule/month`, `/content/[id]/[tab]`)로 바꿔 정적화하는 안은 **채택하지 않았다** — 단축키·빠른 이동·대기열 링크가 전부 바뀌는 URL 계약 변경이라 별도 결정 사항이다(§11).
- 미리보기 탭은 카드 목록·이미지 주소를 **서버가 HTML 에 바로 싣는다.** 전에는 JS 를 받고 → `/api/cards` 를 묻고 → 그제야 이미지를 찾는 3단 연쇄였다.

## 3. 데이터 캐시·재검증 정책

데이터는 유스케이스 → `StudioRepository` 포트 → SQLite 어댑터에서 온다(04 문서). 읽기는 µs 단위지만 한 화면이 같은 목록을 여러 번 읽고, 저장소가 바뀔 때(Postgres 등) 같은 정책이 그대로 필요하다.

| 층 | 정책 | 무효화 |
| --- | --- | --- |
| **읽기 캐시**(`application/read-cache.ts`, 저장소 데코레이터) | 키=읽기 종류, TTL 30초, 최대 32항목(LRU), 같은 키 동시 읽기는 1회로 합침, 결과는 **깊게 얼림**(화면이 고치면 즉시 예외) | 저장소 `revision()` 이 오르면 즉시(쓰기 직후 반영), 아니면 TTL |
| **페이지**(`/`·`/publish`) | `revalidate = 60` | 쓰기 유스케이스가 생기면 `revalidatePath` 로 즉시 — M2 과제 |
| **HTTP** | 카드 이미지 `private, max-age=3600, stale-while-revalidate=86400` + ETag(내용 바뀌면 바뀜) / 빠른 이동 색인 `private, max-age=60, swr=600` | ETag 조건부 요청(304) |
| **이미지 변환 결과** | 디스크 30일(`minimumCacheTTL`) | 원본 주소·폭·품질이 키 |

- 모든 항목에 **상한**이 있다(메모리가 요청 수에 비례해 자라지 않는다).
- 비용: 유스케이스 층이 생기면서 동적 경로 p50 이 +0.0~1.5 ms(`/schedule` 5.3→5.9, 미리보기 3.9→5.4). 정적 경로는 같다.

## 4. 경로 프리페치

| 장치 | 동작 | 이유 |
| --- | --- | --- |
| Next `Link` 기본 | 뷰포트에 들어온 링크를 운영 빌드에서 미리 받음(사이드바·표 행·카드 링크) | 따로 막지 않는다 — 행이 늘어도 보이는 링크만 받는다 |
| **`g` 키** | `g` 를 누르는 순간 이동 후보 4개 화면을 미리 받음(1회) | `g` 다음엔 거의 확실히 이동 키가 온다 |
| **빠른 이동 선택 행** | 선택이 바뀔 때마다 그 화면을 미리 받음 | Enter 직전 100~300 ms 를 번다 |

효과(체감 지연·전환 시간)는 브라우저 계측이 필요해 **미측정**이다.

## 5. 이미지

- **원본 JPEG(120~190 KB, 1600 px)·카드 PNG(~110 KB, 1080 px)를 `/_next/image`(WebP·크기별 파일·디스크 캐시)로 낸다.** `lib/media.ts` 가 주소를 만들고 ui 는 `Media` 값(src·srcset·sizes·width·height·priority)만 받는다.
- 첫 화면 이미지(오늘 히어로)는 `priority`(즉시·높은 우선순위), 나머지는 `loading="lazy"`. `width`·`height` 를 항상 넣어 자리를 미리 잡는다(CLS 대비 — 실측은 미측정).
- 카드 썸네일 8장: PNG 8장(999 KB) → **48 px WebP 8장(42 KB)**. 큰 카드 틀은 448/896 px(1x/2x).
- **AVIF 는 껐다**(실측): 화면당 20 KB 더 줄지만(히어로 48→30 KB) 첫 변환 때 서버 RSS 가 +145 MB(240→384 MB), 변환이 4배 느리다(122→466 ms). 운영자 1~2명 도구에는 손해다.
- **서버 메모리**: 이미지 변환기(sharp)가 뜨면 RSS 가 약 +70 MB(전 185 → 후 255 MB, 경로 1회전 뒤). 변환 결과는 디스크에 남아 재시작 뒤엔 다시 변환하지 않는다.
- 이미지 허용 폭·품질은 `lib/image-config.ts` 한 곳(`next.config.ts` 와 주소 생성기가 같은 값, 어긋나면 400 — `media.test.ts` 가 확인).

## 6. 서체

- 서체는 SIL OFL, 빌드 때 받아 자체 호스팅(런타임 외부 요청 없음), `display: swap`.
- 한글 본문 서체(IBM Plex Sans KR)는 **글자 조각(unicode-range) 약 100개 × 굵기 2(400·600)**로 쪼개져 있어 브라우저가 화면에 쓰인 글자의 조각만 받는다 — 이것이 이미 한글 서체의 subset 이다.
- **미리 받기(preload)는 영문 서체(Plex Mono, 라틴 조각 하나)만 켠다.** 한글 서체에 `preload` 를 켜 봤더니(`subsets: ["latin"]`) 조각 **134개가 전부 `<link rel=preload>`** 로 나가 HTML 이 +4 KB, 브라우저는 모든 화면에서 약 1 MB 를 먼저 받게 되어 즉시 되돌렸다(실측). 이 함정을 `layout.tsx` 주석에 남겼다.
- 굵기는 **400·600 두 단계**다(2026-11-05 사용자 승인, §13). 제목·핵심 숫자·히어로(`heading`·`metric`·`hero`)는 500 에서 400 으로 옮겼다 — macOS 의 Optima 는 Medium 이 없어 500 이 이미 Regular 로 그려지므로 Mac 화면은 그대로이고, Optima 가 없는 기기(Linux·Android)에서만 Plex Medium 대신 Regular 가 쓰인다. 강조(`label`·`title`)는 원래 600 이다.
- 이 추정은 「화면 글자가 걸리는 모든 조각·모든 굵기」의 상한이다(실제로는 쓰는 굵기만 받는다). FOUT·글자 모양 전환 체감은 **미측정**.

## 7. 번들 분할·지연 로드 — 해 보고 버린 것까지

첫 화면 JS(gzip)는 프레임워크 130 KB + 화면 코드 8 KB 다. 화면 코드는 쪼갤 몫이 작다는 것을 먼저 확인했다.

| 시도 | 결과 | 결정 |
| --- | --- | --- |
| 빠른 이동·단축키 대화상자(+ 가상 목록)를 **지연 로드** | 처음 열 때만 받는다. 모든 화면 번들에서 빠짐 | **채택** — `React.lazy` + `Suspense` |
| 같은 것을 `next/dynamic` 으로 | `next/dynamic` 런타임이 gzip **+5 KB** → 분리 이득보다 큼 | 버림 |
| 편 상세 탭 4개를 탭별 지연 로드 | 4개 합쳐 gzip 3.4 KB, 열린 탭 코드는 어차피 바로 필요해 **왕복만 늘어남** | 버림 |
| 서버 컴포넌트에서 `next/image` 의 `getImageProps` 사용 | `next/image` 클라이언트 컴포넌트(gzip **+5.5 KB**)가 모든 화면 번들에 실림 | 버림 → 주소를 직접 만든다(§5) |
| `@yunseo/ui` barrel 에 가상 목록(클라이언트) 포함 | 서버 화면의 barrel 에 클라이언트 경계가 끼어 번들에 샘 | 별도 입구 `@yunseo/ui/virtual` |
| `design-tokens`·`domain`·`ui` 에 `sideEffects` 선언 | 안 쓴 export 가 번들에 실리지 않게(없으면 토큰 표 전체가 실림) | **채택**(`boundaries.test.ts` 가 확인) |

- 클라이언트 섬은 `components/` 로 한정하고 그 안에서 서버 코드·유스케이스·어댑터를 import 하면 린트가 막는다(04 문서).
- 번들 크기 전후: 첫 화면 JS gzip **136.5 → 136.5 KB(동일)**, 빌드 정적 JS 파일 합 932.8 → 935.7 KB(27 → 29개).

## 10. 전후 측정

### 측정 방법

- 환경: Windows 실행기 WSL2, Node 22.23, Next 16.4.4(webpack), `next start`, 루프백(네트워크 지연 0). 같은 스크립트(`scripts/perf/measure.mjs`)로 전·후 각각 새 빌드를 측정했다. 재현: `win auto -- bash scripts/perf/run.sh <이름>`.
- **첫 화면 전송량** = HTML(gzip) + JS(gzip, `nomodule` 폴리필 제외) + CSS(gzip) + 서체(바이트) + 이미지(바이트, `Accept: webp` 로 받은 값). gzip 은 서버가 보낼 값을 같은 수준(6)으로 근사한 값이다.
- **서체**는 CSS 의 `@font-face` 중 화면 글자와 unicode-range 가 겹치고 굵기가 400·500·600 인 파일을 센 **추정 상한**이다(브라우저가 아니라 계산).
- **이미지**는 `<img>`·`srcset`·미리 받기·인라인 배경 주소 중 가정 화면(폭 1440, DPR 1)이 고를 후보 1개. 미리보기 탭은 전 구조에서 `/api/cards` 를 묻고 이어 받는 이미지를 같은 방식으로 흉내 냈다.
- 서버 응답은 경로당 워밍업 3회 + 30회의 p50·p95(ms).
