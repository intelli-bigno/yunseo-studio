# 02. SOP — 한 편의 생산 공정

한 편 = 이벤트 1건에 대한 **카드뉴스 1세트 + Shorts 1편**. 각 단계는 상태(state)이고, 대시보드는 이 상태 기계를 보여주고 움직인다.

```
idea → selected → drafted → verified → rendered → shorts_ready → in_review ─┬→ approved → scheduled → published → measured
                                                                              └→ changes_requested → (drafted | verified | rendered)
```

사람 게이트는 **두 곳**이다: ①소재 선정(selected) ②게시 전 검수(approved). 그 밖 단계는 자동화 대상이되, 실패하면 멈추고 사람에게 알린다.

| # | 단계 | 입력 → 출력 | 누가 | 완료 기준 |
| --- | --- | --- | --- | --- |
| 1 | **소재 선정** | 이벤트 캘린더 후보 → 선정된 이벤트 1건 | 사람 (자동은 후보만) | 이벤트명·일시(시간대)·포맷·게시 예정 시각 확정 |
| 2 | **원고** | 이벤트 + 포맷 프리셋 → 슬롯별 영어 원고 | 사람 또는 LLM 초안 + 사람 수정 | 포맷 슬롯 전부 채움, 글자 수 상한 통과, 톤 금지어 0 |
| 3 | **사실·출처 검증** | 원고 → 주장(claim)별 출처 표 | 자동 검사 + 사람 확인 | 수치·사실 문장마다 출처 URL·접근일·원문 인용 1개 이상, 출처 없는 문장 0 |
| 4 | **카드 렌더** | 검증된 원고 + 브랜드 프리셋 → PNG 7장 | 자동 | 규격(비율·해상도·파일 형식) 검사 통과, 글자 넘침 0 |
| 5 | **Shorts 변환** | 카드·원고 → 세로 영상 1편 + 제목·설명 | 자동 | 길이·비율 검사 통과, 자막이 안전 영역 안 |
| 6 | **검수 (사람 승인 게이트)** | 카드·영상·캡션·출처 표 → 승인/반려 | **사람** | 체크리스트 전 항목 체크 + 승인자 기록 |
| 7 | **게시** | 승인본 → Instagram·YouTube 게시 | 자동 또는 수동 (→ 05) | 게시물 ID·URL 기록, 실패 시 재시도 1회 후 사람 알림 |
| 8 | **성과 기록** | 게시물 ID → 지표 시계열 | 자동 수집 또는 수동 입력 | 게시 후 24h·7d 시점 지표 기록 |

## 단계별 상세

### 1. 소재 선정
- 후보 원천: 정기 발표(중앙은행 회의·고용·물가), 선거, 대형 실적, 사람이 직접 넣은 이슈. (→ 05 이벤트 감지)
- 선정 기준(초안): ①독자 포트폴리오에 경로가 닿는가 ②시나리오가 둘 이상 갈리는가 ③발표 전날 게시가 가능한가(리드타임 ≥ 48h 권장 [미검증 — 실제 제작 시간 실측 후 조정]).
- 같은 이벤트 유형의 직전 게시물과 논지가 겹치면 경고(선례의 "회차 대장" 원칙).

### 2. 원고
- 원고는 슬롯 구조 JSON 으로 저장한다(자유 텍스트 아님). 렌더·Shorts·캡션이 같은 원고를 쓴다 — 사본 금지.
- 캡션·해시태그·Shorts 제목/설명도 이 단계 산출물이다.
- LLM 을 쓰면 프롬프트에 편집 정본·톤 프리셋을 주입한다. LLM 출력은 항상 `draft` 로 표시되고 사람이 저장해야 다음 단계로 간다. [결정 필요 D4 — LLM 사용 여부·비용]

### 3. 사실·출처 검증
- 원고에서 수치·고유명사·날짜가 든 문장을 주장(claim)으로 뽑는다.
- 주장마다 `source_url`, `accessed_at`, `quote`(원문 그대로) 를 단다. 출처 우선순위: 1차 자료(중앙은행·통계청·선관위·기업 공시) > 주요 언론 > 기타.
- "이미 반영된 기대"(슬롯 4)의 시장 가격 수치는 시점이 생명이다 — 접근 시각을 분 단위로 남기고, 게시 직전 재확인 대상으로 표시한다.
- 자동 검사는 "출처 칸이 비었는가", "URL 이 열리는가" 까지만 한다. 내용 일치 판정은 사람이 한다.

### 4. 카드 렌더
- HTML/CSS 템플릿 + 프리셋 → 로컬 헤드리스 렌더로 PNG. (로컬 파일 렌더는 허용 범위)
- 검사: 비율·해상도, 텍스트 박스 넘침, 대비(접근성), 자리표시자(`TBD`) 잔존.

### 5. Shorts 변환
- 기본형(초안): 카드 1·2·5 를 순서대로 보여주며 자막·움직임을 얹은 30~45초 세로(9:16) 영상.
- 음성: 없음(자막만) / TTS / 본인 녹음 중 선택. [결정 필요 D6]
- 카드뉴스와 같은 원고·같은 출처 표를 공유한다. 영상 설명란에 출처 링크.

### 6. 검수 — 사람 승인 게이트 (생략 불가)
체크리스트(초안):
- [ ] 투자 권유로 읽히는 문장 없음 (명령형 매수·매도, 수익 보장, 특정 종목 추천)
- [ ] 시나리오 둘 이상, 한쪽으로 치우치지 않음
- [ ] 모든 수치에 출처, 슬롯 4 수치는 오늘 재확인함
- [ ] 이벤트 일시·시간대 정확
- [ ] 브랜드 자리표시자 없음, 고지 문구(확정본) 포함
- [ ] 카드·영상·캡션 영어 맞춤법
승인자·승인 시각·승인한 산출물의 해시를 기록한다. **승인 뒤 산출물이 바뀌면 승인은 자동 무효**.

### 7. 게시
- 방식은 05 문서에서 판단한 "API 자동 / 예약 / 수동 업로드" 중 결정에 따른다. [결정 필요 D2]
- 어떤 방식이든 승인 해시와 게시 산출물 해시가 일치해야 한다.

### 8. 성과 기록
- 지표(초안): 도달·노출·저장·공유·프로필 방문·팔로우(IG), 조회·평균 시청 시간·구독(YT).
- 초기 목표("프로필만 보고 팔로우")의 대리 지표로 **프로필 방문 → 팔로우 전환**을 본다. [미검증 — API 로 받을 수 있는 지표 범위 확인 필요]
- API 미연동 시 대시보드 수동 입력 폼으로 받는다.
